# EdgePulse 架构

- 版本：1.0.0（2026-10-20）
- 状态：P0–P3 已落地并验收
- 详细设计：[全量设计规范](superpowers/specs/2026-10-20-edgepulse-full-design.md)

## 1. 平面与角色

EdgePulse 分两个平面：

- 控制面：浏览器管理后台，负责登录、权限、系统管理、节点/分组、遥测、告警、固件、命令与审计。
- 数据面：边缘节点上的 `edgepulse-agent`，负责 mTLS 注册、心跳、遥测上报、命令执行与固件下载。

数据库里保留超级管理员与运维人员角色；超级管理员种子 `admin`，运维角色可以在角色的数据范围与菜单授权里配置。

## 2. 模块与依赖

```text
Main
 └─ App                 配置、生命周期、监听器与工作线程装配
     └─ Plugins        各功能控制器与路由注册
         └─ Core       领域服务、仓储、HTTP 交付原语、缓存、插件契约
             └─ Base   响应包络、分页、CSV、数据库、密码、随机数、时间、JSON
```

- `Base`：技术基座，不含业务与 HTTP 语义。`Database` 封装 SQLite/MySQL 连接池，`PasswordHash` 走 OpenSSL PBKDF2，`CsvWriter` 负责 BOM 与 RFC 4180 转义。
- `Core`：领域服务与交付原语。`Auth`、`System`、`Device`、`Telemetry`、`Alarm`、`Firmware`、`Command`、`Ops`、`Cache`、`Http`。
- `Plugins`：认证、系统、监控、工作台、设备、遥测、告警、固件、命令、运维。每个插件只做参数解析、权限校验、响应组装与路由注册。
- `App`：`ApplicationConfiguration` 读 YAML 与环境变量，`Application` 创建 IoContext、数据库、缓存、服务和四类监听器，并负责健康探针、热重载、就绪状态与排空停机。
- `Main`：只解析 `--config`、装载日志、注册信号并调用 `Application::run()`。

依赖方向只向下，没有反向边。`Core` 不依赖具体插件，`App` 只依赖插件暴露的注册函数与依赖结构。

## 3. 监听器与协议

| 端口 | 协议 | 路由范围 |
|---|---|---|
| 8080/TCP | HTTP/1.1 | 健康、认证、系统管理、监控、工作台、设备、遥测、告警、固件、命令、运维 API、WebSocket、SSE、SPA |
| 8443/TCP | HTTPS，ALPN h2/http1.1 | 与 8080 相同的公开 API；Alt-Svc 通告 8443/UDP |
| 8443/UDP | HTTP/3 | 与公开 API 相同；`/api/probe/h3` 只在 QUIC 路由器上存在 |
| 9443/TCP | HTTPS + mTLS | 只挂 Agent 注册/心跳、遥测上报、命令轮询与结果、固件下载/状态、Agent WebSocket |
| 9100/TCP | HTTP/1.1，仅 127.0.0.1 | 引擎 `/metrics`、`/healthz`、`/readyz`、`/debug/loops`、`/debug/connections`、`/debug/log-level` |

公开 API 由同一组插件注册函数挂到 8080、8443/TCP 和 8443/UDP 的路由器上；每条监听器都有自己的路由器与接受协程，避免跨循环共享路由器。h3 的 `/api/probe/h3` 是独立探针：TCP 同路径落到 404，因此「回落 TCP」不能被误判成 h3。

## 4. 存储

- 本地档：SQLite 文件（`var/edgepulse.db`）。
- 生产档：MySQL（`edgepulse.database.driver=mysql`），连接池上限 8，空闲探活由连接池负责。
- 缓存：`edgepulse.redis.enabled=true` 时会话、验证码与登录失败计数走 Redis；否则走进程内 `MemoryKeyValueStore`。
- 迁移：`V1__schema.sql` 到 `V6__firmware_command.sql`，按版本号升序执行，`schema_migrations` 记录 SHA-256；已应用文件的校验和不一致时拒绝启动。
- ID 由应用生成（毫秒左移 10 位 + 进程内序列），保持在 JavaScript 安全整数内，避免 SQLite/MySQL 自增语法分叉，也避免管理端解析丢精度。
- 软删除用于用户、角色、部门、岗位、字典、参数、节点与节点分组；查询统一带 `deleted=0`。
- 节点 `version` 做乐观锁；影响的 0 行区分不存在与版本冲突。

表分域：

| 域 | 表 |
|---|---|
| 系统 | `sys_user`、`sys_role`、`sys_menu`、`sys_dept`、`sys_post`、`sys_dict_type`、`sys_dict_data`、`sys_config` |
| 关系 | `sys_user_role`、`sys_user_post`、`sys_role_menu`、`sys_role_dept` |
| 审计 | `sys_login_log`、`sys_oper_log` |
| 设备 | `biz_node`、`biz_node_group`、`biz_telemetry` |
| 告警 | `biz_alarm_rule`、`biz_alarm` |
| 交付 | `biz_firmware`、`biz_firmware_task`、`biz_command` |
| 迁移 | `schema_migrations` |

## 5. 认证、权限与数据范围

登录链路：

```text
captcha -> login(username,password,captcha,uuid)
  -> 按 IP 失败计数（Redis/内存，10 次/分钟）
  -> 验证码一次性消费
  -> 用户存在且启用
  -> PBKDF2-HMAC-SHA256 校验（工作线程，210000 次）
  -> 读角色/权限码
  -> 生成 32 字节不透明 token，写会话存储（TTL 7200 秒）
  -> 更新 last_login_time，写 sys_login_log
```

- 口令格式：`pbkdf2_sha256$210000$<salt_b64>$<hash_b64>`；16 字节盐、32 字节输出；恒定时间比较。
- 会话每次有效访问滑动续期；`AuthService::authenticate` 是异步的，Redis 档的网络往返不占事件循环。
- 权限码来自 `sys_menu.permission`，超级管理员角色拥有全部菜单与按钮。每个控制器先过 `Web::requireSession`，无会话 401、无权限 403。
- 数据范围按角色 `data_scope` 求并集：`ALL` 直接放行；否则把 `DEPT`/`DEPT_AND_CHILD` 与 `CUSTOM` 展开成部门集合，`SELF` 退化为本人；用户列表、节点列表与写入、操作/登录日志、工作台统计都按同一份范围过滤，永不把「没有角色」回落成全部数据。
- 操作审计由全局中间件记录：写方法、模块、动作、操作人、部门、来源 IP、耗时、结果与脱敏后的请求体；认证入口与 Agent 通道不记入操作日志。

## 6. 设备、遥测、告警、固件与命令

- Agent 在 mTLS 监听器上注册，注册时自报 SHA-256 指纹并与白名单比对；心跳更新在线状态并广播 `node.status`。
- 节点分组是树形结构；节点带 `group_id` 与 `owner_dept_id`，删除分组前检查子分组与节点占用。
- 遥测批量写入按事务落库；最新值按每个指标的最大 ID 取一条；时间序列限制 2000 点；保留天数由配置控制（清理入口在仓储）。
- 告警评估在遥测写入后同步执行：启用规则按节点/指标匹配，比较符支持 `>`、`>=`、`<`、`<=`、`==`；同一规则与节点在恢复前只保留一条未恢复告警；恢复后进入冷却窗口，避免抖动刷屏。
- 告警变更通过 `AlarmNotifier` 同时推送浏览器 WebSocket 的 `alarms` 主题与 SSE `/api/events/alarms`。
- 固件上传走流式正文：边收边写临时文件并增量计算 SHA-256，完成后重命名并写元数据；下载支持 ETag/304 与单段 Range/206。下发时为每个节点创建任务与 `firmware.update` 命令。
- 命令有 `pending → running → succeeded/failed/timeout/canceled` 生命周期；在线 Agent 通过 WebSocket 直推，离线 Agent 用 `/api/agent/commands/next` 轮询，结果从 WebSocket 或 HTTP 回传。
- 浏览器 `/api/ws` 升级后 5 秒内必须发 `{"type":"auth","token":"..."}`；成功后订阅 `nodes`、`alarms`、`commands` 三个主题。Agent `/api/agent/ws` 在 mTLS 上以 `{"type":"hello","nodeId":...}` 登记通道。

## 7. 可观测、热重载与停机

- 引擎 HTTP 服务器输出 `asyn_http_*` 指标；业务注册 `edgepulse_build_info`，`/api/ops/summary` 汇总节点、告警、遥测与命令读数。
- `/readyz` 读取两个原子量：数据库探针结果与就绪标志。停机请求一到，就绪标志先置 false，探针返回 503；随后按 HTTP、HTTPS、mTLS、QUIC、Ops 的顺序排空在途请求，最后从池外线程停止 IoContext。
- 数据库健康探针每 2 秒借一条连接执行驱动级 `probeAlive()`；失败只影响就绪状态，不直接杀进程。
- 配置热重载由 `ConfigManager` 监听配置文件，更新会话 TTL 与验证码 TTL/限流；监听地址与端口变更只写日志提示重启。
- `metrics.enabled=true` 时按 OTLP/HTTP 配置创建导出出口；采集端缺失不会阻止主服务启动之外的其它能力，出口失败计数由引擎统计。
- 生产静态站点：`web/index.html` 存在时，未命中的非 API GET 返回 SPA 入口；`/assets/*` 带长期缓存，其他文件 `no-cache`；`/api/*` 未命中仍返回统一 JSON 404。

## 8. 安全边界

- 所有口令、token、私钥、MySQL/Redis 凭据只从环境变量或未跟踪文件读取。
- 运维口只监听回环；`/metrics` 与调试端点需要 Bearer，`/healthz` 与 `/readyz` 不需要凭据。
- 安全响应头：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、CSP；HSTS 只在 TLS 上。
- 固件上传限制单份大小（默认 256 MiB）并拒绝路径穿越；文件落盘名为服务端生成 ID + 清洗后的文件名。
- 统一 envelope 不回显数据库驱动原文；审计日志对 `password`、`token`、`captcha` 等字段脱敏。
- mTLS 在 TLS 层校验 CA 并要求客户端证书；指纹白名单在注册时按 Agent 自报值二次校验。当前引擎不向 HTTP 处理器暴露对端证书，因此逐请求指纹绑定仍是边界。

## 9. 明确不做

P4 的边缘反向代理、UDP 遥测、OIDC、多租户按原设计另行设计。多进程 worker 编排、每节点独立 CA、真正的跨进程实时扇出也不在本次默认运行形态内。
