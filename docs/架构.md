# EdgePulse 架构

- 版本：1.3.0（2026-10-25）
- 状态：P0–P8 功能已落地并进入验收

## 1. 平面与角色

EdgePulse 分两个平面：

- 控制面：浏览器管理后台，负责登录、权限、系统管理、节点/分组、遥测、告警、固件、命令与审计。
- 数据面：边缘节点上的 `edgepulse-agent`，负责 mTLS 注册、心跳、遥测上报、命令执行与固件下载。

数据库里保留超级管理员与运维人员角色；超级管理员种子 `admin`，运维角色可以在角色的数据范围与菜单授权里配置。

## 2. 模块与依赖

```text
Main
 └─ App                 配置、生命周期、监听器与工作线程装配
     └─ Plugins        各功能控制器与路由注册
         └─ Core       领域服务、仓储、HTTP 交付原语、缓存、插件契约
             └─ Base   响应包络、分页、CSV、数据库、密码、随机数、时间、JSON
```

- `Base`：技术基座，不含业务与 HTTP 语义。`Database` 封装 SQLite/MySQL 连接池，`PasswordHash` 走 OpenSSL PBKDF2，`CsvWriter` 负责 BOM 与 RFC 4180 转义，`OutboundUrlGuard` 负责出站 Webhook 的地址校验。
- `Core`：领域服务与交付原语。`Auth`、`System`、`Device`、`Telemetry`、`Alarm`、`Firmware`、`Command`、`Notification`、`Ops`、`Cache`、`Http`、`Metrics`。设备域内的 `AgentAuthorization` 统一校验 Agent 连接证书与节点登记指纹；`Enrollment` 管理一次性注册/改绑令牌；`NodeLifecycle` 处理心跳超时判离线与系统告警销案；`AgentCertificateAuthority` 用控制面内部 CA 签发 Agent 证书，`AgentCertificateRepository` 保存每次签发历史；`NodeConfig` 保存设备影子、不可变修订与回滚；固件域的 `FirmwareSignatureVerifier` 按 key id 加载 Ed25519 公钥并验签；`ApiTokenService` 负责哈希令牌的签发、轮换、吊销与鉴权；`MfaService` 负责 TOTP、加密秘密、恢复码与登录挑战；`Http` 下的 `IdempotencyMiddleware` 与 `IdempotencyRepository` 提供写请求重放；`Metrics::BusinessMetrics` 汇总进程级业务读数。
- `Plugins`：认证、系统、监控、工作台、设备、遥测、告警、固件、命令、运维。设备插件同时提供注册令牌、节点详情、证书吊销与配置下发路由；认证插件提供 MFA 路由，系统插件提供 API 令牌与管理员重置路由。每个插件只做参数解析、权限校验、响应组装与路由注册。
- `App`：`ApplicationConfiguration` 读 YAML 与环境变量，`Application` 创建 IoContext、数据库、缓存、服务和五类监听器，并负责健康探针、OpenAPI 静态契约、热重载、就绪状态、离线扫描、保留期清理与排空停机。
- `Main`：只解析 `--config`、装载日志、注册信号并调用 `Application::run()`。

依赖方向只向下，没有反向边。`Core` 不依赖具体插件，`App` 只依赖插件暴露的注册函数与依赖结构。

## 3. 监听器与协议

| 端口 | 协议 | 路由范围 |
|---|---|---|
| 8080/TCP | HTTP/1.1 | 健康、认证、系统管理、监控、工作台、设备、遥测、告警、固件、命令、运维 API、WebSocket、SSE、SPA |
| 8443/TCP | HTTPS，ALPN h2/http1.1 | 与 8080 相同的公开 API；Alt-Svc 通告 8443/UDP |
| 8443/UDP | HTTP/3 | 与公开 API 相同；`/api/probe/h3` 只在 QUIC 路由器上存在 |
| 9443/TCP | HTTPS + mTLS | 只挂 Agent 注册/心跳、证书续期、遥测上报、命令轮询与结果、配置拉取/上报、固件下载/状态、Agent WebSocket |
| 9100/TCP | HTTP/1.1，默认仅 127.0.0.1 | 引擎 `/metrics`、`/healthz`、`/readyz`、`/debug/loops`、`/debug/connections`、`/debug/log-level`；生产样例可绑 `0.0.0.0` 供容器抓取 |
| 9555/UDP | UDP 遥测 | HMAC-SHA256 签名的遥测数据报；默认关闭，密钥只从环境变量读取 |

公开 API 由同一组插件注册函数挂到 8080、8443/TCP 和 8443/UDP 的路由器上；每条监听器都有自己的路由器与接受协程，避免跨循环共享路由器。h3 的 `/api/probe/h3` 是独立探针：TCP 同路径落到 404，因此「回落 TCP」不能被误判成 h3。

## 4. 存储

- 本地档：SQLite 文件（`var/edgepulse.db`）。
- 生产档：MySQL（`edgepulse.database.driver=mysql`），连接池上限 8，空闲探活由连接池负责。
- 缓存：`edgepulse.redis.enabled=true` 时会话、验证码与登录失败计数走 Redis；否则走进程内 `MemoryKeyValueStore`。
- 迁移：`V1__schema.sql` 到 `V20__agent_certificate_renewal.sql`，按版本号升序执行，`schema_migrations` 记录 SHA-256；已应用文件的校验和不一致时拒绝启动。V15 增加证书到期/吊销列、离线扫描索引与注册令牌表；V16 增加设备影子与配置修订表；V17 增加固件签名字段；V18 增加账号失败计数与锁定截止时刻；V19 增加 API 令牌、写请求幂等与两步验证表，并写入菜单 1210–1213 与角色授权；V20 在 `biz_node` 增加 `previous_cert_fingerprint`/`previous_cert_not_after`，并新增 `biz_agent_certificate` 签发历史表。
- ID 由应用生成（毫秒左移 10 位 + 进程内序列），保持在 JavaScript 安全整数内，避免 SQLite/MySQL 自增语法分叉，也避免管理端解析丢精度。
- 软删除用于用户、角色、部门、岗位、字典、参数、节点与节点分组；查询统一带 `deleted=0`。
- 节点 `version` 做乐观锁；影响的 0 行区分不存在与版本冲突。节点配置用 `desired_version` 做第二次乐观锁，版本冲突返回 409。

表分域：

| 域 | 表 |
|---|---|
| 系统 | `sys_user`、`sys_role`、`sys_menu`、`sys_dept`、`sys_post`、`sys_dict_type`、`sys_dict_data`、`sys_config` |
| 关系 | `sys_user_role`、`sys_user_post`、`sys_role_menu`、`sys_role_dept` |
| 审计 | `sys_login_log`、`sys_oper_log` |
| 企业身份 | `sys_api_token`、`sys_idempotency`、`sys_user_mfa` |
| 设备 | `biz_node`、`biz_node_group`、`biz_telemetry`、`biz_agent_enrollment`、`biz_agent_certificate`、`biz_node_config`、`biz_node_config_revision` |
| 告警 | `biz_alarm_rule`、`biz_alarm` |
| 交付 | `biz_firmware`、`biz_firmware_task`、`biz_command` |
| 迁移 | `schema_migrations` |

## 5. 认证、权限与数据范围

登录链路：

```text
captcha -> login(username,password,captcha,uuid)
  -> 按 IP 失败计数（Redis/内存，10 次/分钟）
  -> 验证码一次性消费
  -> 用户存在且启用
  -> PBKDF2-HMAC-SHA256 校验（工作线程，210000 次）
  -> 已启用两步验证？写 300 秒挑战，返回 challengeToken，不签发会话
  -> 否则读角色/权限码
  -> 生成 32 字节不透明 token，写会话存储（TTL 7200 秒）
  -> 更新 last_login_time，写 sys_login_log
```

- 口令格式：`pbkdf2_sha256$210000$<salt_b64>$<hash_b64>`；16 字节盐、32 字节输出；恒定时间比较。
- 口令策略在新建、管理员重置与用户改密三处共用：最小长度 8–64 可配，可要求同时包含大写、小写、数字与符号；策略只约束新设置的口令，既有账号的原口令仍可登录。
- 登录失败先按来源 IP 限频（默认 10 次/分钟，超过返回 429），再按账号在窗口内累计失败；达到阈值后写入锁定截止时刻，触发锁定的那次仍返回统一 401，之后返回 423 并给出配置的锁定时长（分钟）而非剩余时间。成功登录与管理员重置会清空失败计数与锁定。
- 会话每次有效访问滑动续期；`AuthService::authenticate` 是异步的，Redis 档的网络往返不占事件循环。
- `AuthService::authenticate` 是唯一认证汇合点：先查浏览器会话，未命中再按 `ep_api_` 形状查 API 令牌，最后统一校验租户启停。不存在第二套并行鉴权；MFA 只在登录阶段介入，不改变已签发会话的校验路径。
- API 令牌身份带运行期标记 `apiToken=true`，`platformAdmin` 固定为 false；`requireSession` 在权限码为空时拒绝令牌，`/api/auth/routes` 与 `/api/auth/logout` 只接受浏览器会话，浏览器 WebSocket 校验器与改密入口也显式拒绝令牌；`/api/auth/me` 保留给令牌自省。令牌身份与浏览器会话共享同一套控制器权限码与数据范围，差异只在来源与 scope 交集。
- 权限码来自 `sys_menu.permission`，超级管理员角色拥有全部菜单与按钮。每个控制器先过 `Web::requireSession`，无会话 401、无权限 403。
- 数据范围按角色 `data_scope` 求并集：`ALL` 直接放行；否则把 `DEPT`/`DEPT_AND_CHILD` 与 `CUSTOM` 展开成部门集合，`SELF` 退化为本人；用户列表、节点列表与写入、操作/登录日志、工作台统计都按同一份范围过滤，永不把「没有角色」回落成全部数据。
- 公网 HTTP、HTTPS 与 h3 共用一个令牌桶，按 `server.rate_limit` 限流，超速返回 429 与 `Retry-After`；Agent 与运维口不参与该桶。
- 操作审计由全局中间件记录：写方法、模块、动作、操作人、部门、来源 IP、耗时、结果与脱敏后的请求体；认证入口与 Agent 通道不记入操作日志。

### 5.1 Agent 证书身份与注册模式

| 场景 | 凭证要求 |
|---|---|
| 除 `/api/agent/register` 外的 `/api/agent/*` | 连接出示的叶证书指纹必须等于节点登记的 `certFingerprint`；不一致返回 403，证书已吊销同样返回 403 |
| 注册入口 `/api/agent/register` | 没有可比的登记指纹；校验正文 `certFingerprint` 与本次连接出示的叶证书一致，不一致返回 403 |
| 新节点首次注册（`enrollment_mode=required`） | 必须带 `enroll` 令牌；令牌可用 `nodeName` 限定节点名 |
| 已有节点同指纹重注册 | 不需要令牌；刷新 `agentVersion`、`lastSeen` 与证书到期时间 |
| 已有节点更换证书（`required`） | 必须带 `rebind` 令牌；`enroll` 令牌不能改绑，`rebind` 令牌不能新建节点 |
| 已有节点自动续期（启用 `agent_ca`） | 连接证书必须匹配当前指纹或未过期的 `previousCertFingerprint`；不需要令牌，节点标识与租户不变 |
| `off` 模式 | 只校验 mTLS 的 CA 链与可选指纹白名单，不要求令牌；仅供开发与测试 |

- 令牌明文以 `ep_enroll_` 开头，只在签发响应出现一次；库存只写 SHA-256，列表按 `expires_at/used_at/revoked_at` 派生 `active/used/expired/revoked`，永不回显明文或哈希。有效期限制在 300 到 2592000 秒。
- 注册事务把令牌消费与节点写入放在同一笔事务：动作由事务内读到的节点状态决定，令牌条件同时钉住租户、动作、节点名、未使用、未吊销与未过期；并发注册冲突返回 409 让 Agent 重试。
- 注册时从叶证书解析并记录 `certNotAfter`；管理端节点详情可读 `certNotAfter`、`previousCertFingerprint`、`previousCertNotAfter` 与 `certRevokedAt`。吊销会清空当前与重叠指纹、把节点置为离线、销案离线告警，并以 1008 关闭该节点已建立的 Agent WebSocket。
- `required` 模式下缺少令牌或令牌不可用统一返回 403，不透露令牌是过期、已用还是节点名不匹配。
- 自动续期：`POST /api/agent/certificate/renew` 接收 `{nodeId,csrPem}`，按连接证书匹配当前或未过期的上一枚指纹，检查租户启用与每节点 60 秒签发间隔；内部 CA 校验 CSR 自签、公钥强度与 `CA:FALSE` 后签发，`rotateCertificate` 以节点 `version` 为条件在单事务里写当前指纹、`previous_cert_not_after = min(旧 notAfter, now + overlap_hours)` 与一条 active 历史。版本冲突时按最新节点重新认证后最多再写一次，仍冲突返回 409。续期不改变节点标识与租户，也不同于 `rebind` 的整节点改绑。
- 历史表 `biz_agent_certificate` 每次签发一行（序列号、指纹、主题、生效/到期、状态、签发时间、吊销时间）；轮换把旧 active 改为 previous，吊销把 active 与 previous 一起改为 revoked 并写 `revoked_at`。

### 5.2 API 令牌

- `sys_api_token` 只保存 `token_hash`、`token_prefix`、`scopes`、到期/吊销时间与最近使用时间；明文是 `ep_api_` 加 32 字节随机数的十六进制，只在创建或轮换响应出现一次。
- 创建时校验名称 1–64 字符、scope 非空且属于 owner 当前权限，重复 scope 直接返回 400；有效期默认 30 天，允许 300 到 31536000 秒。创建与轮换只接受浏览器会话；令牌会话即使带 `system:token:add/edit` 也返回 403，避免签发没有父级到期上限与级联吊销的子令牌。
- 鉴权按 `token_hash` 查行，再查 `previous_hash` 的重叠窗口；随后校验 owner 状态、行与 owner 的租户一致性、租户启停。权限取 scope 与 owner 当前权限的交集，全部被收回即 401。
- 轮换保留原到期时间，把旧哈希写入 `previous_hash` 并给 1 小时重叠窗口；吊销只写 `revoked_at`，列表保留已吊销行。`last_used_at` 由条件更新节流为每分钟最多一次，写失败只记日志、不影响鉴权。
- 列表按接口权限返回本租户全部令牌，不按 owner 或 scope 过滤；轮换只接受浏览器会话，吊销对令牌会话仍要求本人且 scope 不宽于自身，浏览器会话只需对应接口权限。跨租户、已吊销、已过期与并发轮换分别按 404/409 收口，缺接口权限返回 403。

### 5.3 两步验证

- TOTP 按 RFC 6238（HMAC-SHA1、6 位、30 秒）校验 ±1 步，并用 `last_used_step` 条件更新拒绝重放；秘密以 AES-256-GCM 加密落库，nonce 随机、tag 附在密文尾部，加密密钥来自 `EDGEPULSE_MFA_KEY`。
- 待启用秘密加密后放缓存 `edgepulse:mfa:setup:<userId>`，TTL 600 秒；同时在 `sys_user_mfa` 写入一条停用记录。输错验证码不会销毁设置流程；启用时用一次条件 UPDATE 同时写入密文、恢复码、步号与启用位，只有仍持有当前待启用密文的流程能命中。
- 恢复码为 `xxxx-xxxx`，以主密钥为键做 HMAC-SHA256 后存 JSON，逐枚 CAS 删除，第二次提交同一枚失败。数据库单独泄露无法离线还原 40 位随机码。
- 登录挑战放缓存 `edgepulse:mfa:challenge:<token>`，值为用户、租户、来源 IP、失败次数与绝对过期时刻；`take` 原子读取并删除，300 秒过期、单个挑战最多 5 次失败，来源 IP 必须与口令登录一致。挑战不落库。
- 设置口令复核、启用、关闭、换发恢复码与登录挑战失败共用每用户 5 次/300 秒的失败计数；签发新挑战与接受口令复核前都先检查该计数，第 6 次起返回 429。设置口令正确但未完成第二因素不会清零，完成挑战校验或成功的管理操作才清零。管理员重置删除记录、待启用缓存与该计数，要求 `system:user:edit` 并按会话租户校验目标。
- 本阶段是用户自助启用，没有租户级强制开关，也没有密钥轮换或 AAD 绑定。

### 5.4 写请求幂等键

- 中间件顺序是安全头、全局限流、操作审计、幂等键；只处理 `POST/PUT/PATCH/DELETE`，且必须同时带有效 Bearer 与 `Idempotency-Key`。鉴权先于占位，吊销后的会话不能靠缓存拿到旧响应。
- `sys_idempotency` 以 `(token_hash, key_hash)` 唯一；行内保存请求指纹、方法、路径、`in_progress/completed` 状态、状态码、content-type、响应正文与首次 `x-request-id`。TTL 24 小时。
- 请求指纹是 `idem-v2`、方法、完整 URI、`Content-Type`、`Content-Encoding`、排序权限码摘要与正文的 SHA-256；权限降级、查询串或表示头变化都会判冲突。
- 命中完成态重放状态码、content-type、正文与链路标识，并加 `Idempotent-Replayed: true`；指纹不同返回 409，处理中返回 409。处理中占位有 90 秒租约，超时可被接管，接管按至少一次语义执行。
- 401/403/5xx、超过 256 KiB 的响应与处理器异常都会清掉占位。认证、Agent、WebSocket、SSE、流式固件上传、令牌、注册令牌、用户/租户写入与反向代理前缀不进入幂等表。
- 后台保留期协程调用 `pruneExpired` 删除到期行；保留期清理与离线扫描一样是进程内任务，多实例会重复执行。

### 5.5 OpenAPI 契约

- `scripts/generate-openapi.py` 扫描 `src/**/*.cpp` 的 `router.get/post/put/del/patch` 与流式变体字面量，把 `:name` 归一为 `{name}`；摘要、schema、安全与响应状态由 `docs/openapi-notes.json` 补齐，生成 `frontend/public/openapi.json`。
- 生成器拒绝重复注册、非字面量路径（反向代理前缀是唯一例外）、悬空 notes、未知 schema/方法/安全方案与媒体类型；`--check` 逐字节比较，CI 在构建前执行。
- 服务端在 `web_root` 下一次性读取 `openapi.json` 到内存，启动时解析并校验它含字符串 `openapi` 与对象 `paths`；`GET /api/openapi.json` 匿名返回。重建 `web/` 或替换契约文件后必须重启服务。文件缺失、空、语法不完整或缺少这两个字段时返回带 `x-openapi-error: missing` 的 JSON 404，不会落进 SPA 兜底。
- 契约覆盖浏览器与自动化 API，包含 `/api/health`；Agent 通道、`/api/ws`、SSE、运维口的 `/healthz`、`/readyz` 与动态反代前缀不在其中。当前没有 `/api/v1` 前缀。

## 6. 设备、遥测、告警、固件与命令

- Agent 在 mTLS 监听器上注册，自报的 SHA-256 指纹必须与连接出示的叶证书一致，再与白名单比对；注册成功后所有 `/api/agent/*` 请求都复用同一份证书绑定校验。心跳更新 `last_seen` 与在线状态并广播 `node.status`。Agent WebSocket 升级后用同一份对端身份复核节点登记值，明文链路不做绑定。
- 节点生命周期：后台每 `offline_sweep_seconds` 扫描一次，超过 `heartbeat_timeout_seconds` 未心跳的在线节点转为 `offline`，生成 `rule_id=0`、`metric=node.online`、级别 `critical` 的系统告警并广播状态；下一次心跳恢复在线并把该告警置为 `resolved`。扫描首轮延后 10 秒，给启动中的 Agent 留出重连窗口；手工创建但从未心跳的节点 `last_seen` 为空，不参与扫描。
- 节点分组是树形结构；节点带 `group_id` 与 `owner_dept_id`，删除分组前检查子分组与节点占用。
- 遥测批量写入按事务落库；最新值按每个指标的最大 ID 取一条；时间序列限制 2000 点；保留天数由配置控制（清理入口在仓储）。
- 设备影子：`PUT /api/nodes/:id/config` 用 `expectedVersion` 做乐观锁，配置正文规范化后按 SHA-256 判定漂移；每次下发写一条不可变修订并创建 `config.apply` 命令。Agent 从心跳的 `desiredConfigVersion` 或 `/api/agent/nodes/:id/config` 拉取，回报版本、正文与状态后由服务端重算摘要；期望与上报的版本、摘要及 `applied` 状态同时相符才算 `inSync`。回滚选一条历史修订，作为新版本重新下发。
- 告警评估在遥测写入后同步执行：启用规则按节点/指标匹配，比较符支持 `>`、`>=`、`<`、`<=`、`==`；同一规则与节点在恢复前只保留一条未恢复告警；恢复后进入冷却窗口，避免抖动刷屏。
- UDP 遥测：默认关闭；启用后监听 `edgepulse.udp_telemetry` 配置的端口，数据报用 `EDGEPULSE_UDP_TELEMETRY_SECRET` 做 HMAC-SHA256，校验时间窗与随机串重放，再走与 HTTP 相同的节点校验、落库与告警评估。
- 告警变更通过 `AlarmNotifier` 同时推送浏览器 WebSocket 的 `alarms` 主题与 SSE `/api/events/alarms`。
- 固件上传走流式正文：边收边写临时文件并增量计算 SHA-256，完成后重命名并写元数据；下载支持 ETag/304 与单段 Range/206，但必须带 `nodeId` 且与连接证书绑定的节点、租户一致。下发时为每个节点创建任务与 `firmware.update` 命令。
- 固件签名覆盖文件 SHA-256 的 32 字节原始摘要，算法标识 `ed25519-sha256`，签名字节以标准 Base64 传输。信任键目录按 PEM 文件名 stem 作为 key id 加载 Ed25519 公钥；上传带 `X-Firmware-Signature` 与 `X-Firmware-Key-Id`，`require_signature=true` 时缺签名在收正文前拒绝，验签失败会删除已落盘成品。下载只在记录确实带签名时回传三个签名头，历史未签名固件仍可下载但不能在被强制签名的实例上下发或回滚。
- 命令有 `pending → running → succeeded/failed/timeout/canceled` 生命周期；在线 Agent 通过 WebSocket 直推，离线 Agent 用 `/api/agent/commands/next` 轮询，结果从 WebSocket 或 HTTP 回传。
- 浏览器 `/api/ws` 升级后 5 秒内必须发 `{"type":"auth","token":"..."}`；成功后订阅 `nodes`、`alarms`、`commands` 三个主题。Agent `/api/agent/ws` 在 mTLS 上以 `{"type":"hello","nodeId":...}` 登记通道。

### 6.1 生产 Agent 进程

`agent/` 是随仓库交付的 `edgepulse-agent`，与控制面共用 `Base` 与引擎的 HTTP、WebSocket、数据库原语：

- 配置与身份：`AgentConfiguration` 读取 YAML，相对路径按配置文件目录归一；注册与改绑令牌只按环境变量名读取。`AgentIdentity` 从证书提取 SHA-256 指纹与到期时间，POSIX 上拒绝同组或其他用户可读的私钥。
- 状态与队列：`AgentState` 用单个 SQLite 连接保存节点标识、升级状态、遥测队列与命令结果队列；队列 FIFO、按上限淘汰，服务端确认后才删除，重启后继续补报。
- 客户端与命令通道：`AgentClient` 负责注册、心跳、命令轮询、结果/遥测/配置回报与固件下载；`AgentWebSocket` 在 mTLS 上建立 wss 长连接并完成 hello，未连接时立即轮询、连接确认后暂停轮询，断线或正常关闭后恢复轮询，并以 30 秒文本 ping 保活。`CommandDispatcher` 按命令标识去重，未知类型按失败上报；心跳成功后会补拉一次命令，覆盖 hello/重连窗口。
- 执行器：`ConfigExecutor` 规范化并原子落盘配置，应用钩子失败时恢复旧文件；`DiagnosticsExecutor` 汇总版本、状态、指标与有界日志尾；`FirmwareExecutor` 流式下载、校验 SHA-256 与 Ed25519 签名后运行安装钩子；`RestartExecutor` 标记重启，由 `CommandDispatcher` 在结果入队并尝试上报后调用平台重启处理器；`UpdateExecutor` 验签升级包、写入待上报状态后脱离启动安装器。外部程序统一经 `ProcessRunner` 直接执行，不经过 shell，限时并限制输出。
- 证书续期：`AgentCertificateManager` 生成 P-256 私钥与 CSR，校验服务端签回的 PEM 标签、到期时间、公钥配对、CA 链与剩余有效期必须大于续期提前量，通过后先用临时 TLS 上下文验证再原子替换私钥（0600）与证书；安装前留 `.bak` 与 `.install-pending` 标记，启动时按标记恢复中断的替换。`AgentApplication::runCertificateRenewal` 是第五个常驻协程：`agent.certificate.renewal_enabled` 为 true 时才启动，按 `renew_before_days` 判断到期窗口，成功后调用 `AgentClient::reloadIdentityFromDisk` 整体替换 HTTP 客户端并让 `AgentWebSocket` 重载 TLS 上下文，进程不重启；403 停止自动续期，其余可重试失败按 5/10/30/60/300 秒退避，HTTP 400 在默认序列上最长等待 20 分钟（300 秒 × 4）。生成与安装经阻塞执行器执行，提交前复制动作，停机销毁协程帧后排队任务仍持有自己的副本与证书管理器。
- 采集与服务托管：`TelemetryCollector` 从 `/proc` 与磁盘统计采样 CPU、内存、磁盘占用率，`TelemetryPublisher` 直传失败时入队并按 500 条分批补报。`AgentApplication` 装配状态、日志、身份与注册并常驻运行；`ServiceHost` 在 Windows SCM 下托管同一套生命周期。Linux 与 Windows 打包脚本生成逐文件 SHA-256 的 `manifest.json`、`checksums.sha256` 与包内 `manifest.sig`，并在提供私钥时对归档本身签名，写出 `<包名>.sig` 与 `<包名>.json`。
- 升级：新版本在首次成功心跳后写 `update-health`；安装器在启动服务前写 `update-expected`，手工升级也靠它确认健康。安装器在时限内未见健康标记或启动失败时恢复旧二进制、写 `update-rollback`，由旧版本补报失败结果。

## 7. 可观测、热重载与停机

- 引擎 HTTP 服务器输出 `asyn_http_*` 指标；业务注册 `edgepulse_build_info`，`BusinessMetrics` 另登记 `edgepulse_nodes_online`、`edgepulse_nodes_offline`、`edgepulse_alarms_open`、`edgepulse_commands_pending`、`edgepulse_agent_certs_expiring_7d`、`edgepulse_firmware_unsigned` 六个仪表，以及离线转换、身份拒绝与 Webhook 地址拒绝三个累计计数器；`/api/ops/summary` 汇总节点、告警、遥测与命令读数。
- `/readyz` 读取两个原子量：数据库探针结果与就绪标志。停机请求一到，就绪标志先置 false，探针返回 503；随后按 HTTP、HTTPS、mTLS、QUIC、Ops 的顺序排空在途请求，最后从池外线程停止 IoContext。
- 数据库健康探针每 2 秒借一条连接执行驱动级 `probeAlive()`；失败只影响就绪状态，不直接杀进程。
- 配置热重载由 `ConfigManager` 监听配置文件，更新会话 TTL 与验证码 TTL/限流；监听地址与端口变更只写日志提示重启。
- `metrics.enabled=true` 时按 OTLP/HTTP 配置创建导出出口；采集端缺失不会阻止主服务启动之外的其它能力，出口失败计数由引擎统计。
- 生产静态站点：`web/index.html` 存在时，未命中的非 API GET 返回 SPA 入口；`/assets/*` 带长期缓存，其他文件 `no-cache`；`/api/*` 未命中仍返回统一 JSON 404。

## 8. 安全边界

- 所有口令、token、私钥、MySQL/Redis 凭据只从环境变量或未跟踪文件读取。
- 运维口默认只监听回环；生产样例为容器或 Prometheus 抓取可绑 `0.0.0.0`，此时必须用主机防火墙或网络策略限制来源。`/metrics` 与调试端点需要 Bearer，`/healthz` 与 `/readyz` 不需要凭据。
- 安全响应头：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、CSP；HSTS 只在 TLS 上。
- 固件上传限制单份大小（默认 256 MiB）并拒绝路径穿越；文件落盘名为服务端生成 ID + 清洗后的文件名。强制签名时，未签名固件不能上传、部署或回滚。
- 统一 envelope 不回显数据库驱动原文；审计日志对 `password`、`token`、`captcha` 等字段脱敏。注册令牌与 API 令牌明文只在签发响应出现一次，列表与日志都不含明文或哈希。
- TOTP 秘密与恢复码不以可逆或可离线爆破的形式落库；登录挑战与待启用秘密只放缓存，成功后立即删除。幂等表不接收认证、令牌、用户/租户写入与流式上传，避免一次性明文或口令被 24 小时缓存。
- mTLS 在 TLS 层校验 CA 并要求客户端证书；除 `/api/agent/register` 外的所有 `/api/agent/*` 请求都要求连接叶证书指纹等于节点登记的当前指纹或未过期的 `previousCertFingerprint`，注册入口改为校验正文 `certFingerprint` 与连接出示的叶证书一致；Agent WebSocket 升级后同样复核，明文链路（开发与测试）不做绑定。重叠窗口只放宽应用层指纹比较，TLS 链校验始终有效；没有 CRL/OCSP，吊销不会让已签发证书在 TLS 层失效。
- Webhook 出站做 SSRF 校验：默认拒绝回环、私网、CGNAT、组播、保留与文档示例段，以及 IPv6 回环、唯一本地、组播与文档段；IPv4-mapped IPv6 按内嵌 IPv4 判断，内嵌私网或保留 IPv4 的映射地址同样拒绝。`allow_private_webhooks=true` 只影响上述普通私网/保留段，云元数据主机名与已知元数据端点、整个 IPv4 链路本地段 `169.254.0.0/16`、IPv6 链路本地段 `fe80::/10` 始终拒绝；每次投递前复检一次，命中只记失败投递与计数。
- 登录失败按 IP 限频、按账号累计并锁定；口令策略在新建、重置与改密三处生效；公开 HTTP/HTTPS/h3 共用令牌桶，超速返回 429 与 `Retry-After`。

## 8.1 边缘反向代理

`edgepulse.reverse_proxy.enabled=true` 时，公开路由器在 API 路由之后、站点兜底之前注册 `prefix` 与 `prefix/*`：

- 默认把 `/edge/...` 转发到 `upstream`，可按配置剥离前缀；
- 只转发 `Accept`、`Accept-Language`、`Content-Type`、`If-None-Match`、`If-Modified-Since`、`Range`、`User-Agent` 与 `X-Forwarded-For`，不透传 EdgePulse 的 Authorization/Cookie；
- 可要求 EdgePulse 会话与权限码；请求/响应正文各有上限，上游超时按配置；浏览器断开时入站取消令牌会传给上游，不再等待没人要的响应；
- 不做 WebSocket 升级与流式大响应转发，适合设备管理 API 这类请求/响应型上游。

## 8.2 OIDC 登录

- 配置 `edgepulse.oidc.*` 后，`/api/auth/oidc/start` 生成 state、nonce 与 PKCE，跳转 IdP；`/api/auth/oidc/callback` 换 token、校验 RS256 ID Token 的签名与 iss/aud/exp/nonce，再回前端。
- 回调只把一次性 code 放进 URL，前端用 `/api/auth/oidc/exchange` 换会话令牌，长 token 不进 URL。
- 身份按邮箱映射本地用户；`auto_provision=true` 时自动建号并分配默认角色/部门，外部身份使用随机口令哈希，不能走口令登录。
- 只支持 RS256 与授权码 + PKCE；issuer/redirect_uri 必须是 HTTPS 或本机回环地址。

## 8.3 多租户

- `sys_tenant` 保存租户编码、名称与启停状态；默认租户 `default`（id=1）承接升级前的全部数据。
- 登录请求可带 `tenantCode`，缺省为 `default`；用户名全局唯一，但用户行带 `tenant_id`，登录按租户过滤。
- 会话快照携带 `tenantId / tenantCode / tenantName / platformAdmin`；平台管理员 `allTenants=true`，可跨租户读写。
- 实时推送按租户分区：浏览器 WebSocket 订阅 `nodes:<tenantId>` 等租户主题，平台管理员订阅跨租户主题；告警 SSE 按订阅者租户过滤。启用 Redis 时事件经 `edgepulse:events` 发布，其他实例订阅后只在本地扇出。
- 租户级数据：用户、节点、节点分组、遥测、告警规则与告警、固件与任务、命令、操作/登录日志、运维总览、角色、部门、岗位与字典。仓储统一接收 `TenantScope`，控制器按会话派生 `scoped()` 视图；子记录（命令、固件任务）继承目标节点/固件的租户。
- 平台级共享配置：菜单与参数。租户管理员角色随租户初始化生成，只能把自身已有权限授予新角色；不能管理租户或平台参数。
- Agent 注册可带 `tenantCode`，节点归属该租户；心跳、命令轮询与结果回写按节点标识全租户查找，再以节点租户约束子记录。
- OIDC 通过 `edgepulse.oidc.tenant_code` 指定外部身份归属租户，自动建号落在该租户内。
- 停用租户立即拒绝新登录；已签发的浏览器会话最多在一个 5 秒租户状态缓存 TTL 内失效，平台管理员不受租户启停限制；API 令牌在每次请求时直接校验 owner 与租户状态，停用立即失效。

## 9. 明确不做

UDP 遥测、边缘反向代理、OIDC、多租户、API 令牌、TOTP 两步验证、写请求幂等与 OpenAPI 3.1 均已落地。当前仍使用 `/api`，没有 `/api/v1` 版本前缀；MFA 是用户自助启用，没有租户级强制策略；API 令牌没有独立速率限制与父令牌级联吊销。反代只做 HTTP 请求/响应转发，不代理 WebSocket 升级与流式大响应。多进程 worker 编排、每个节点独立 CA（当前是一个共享的内部 CA）、真正的跨进程实时扇出也不在本次默认运行形态内。

单实例边界仍然成立：离线扫描、保留期清理与业务指标刷新都是进程内周期任务，没有选主或分布式锁。多实例挂同一个 MySQL 时这些任务会在每个实例各跑一遍，写入本身幂等，但重复扫描与重复清理是已知开销；需要严格单飞时应在部署层只保留一个启用周期任务的实例。
