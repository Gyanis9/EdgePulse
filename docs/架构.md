# EdgePulse 架构

- 版本：P0（2026-10-20）
- 状态：P0 验收通过；P1–P4 按阶段推进
- 详细设计：[设计规范](superpowers/specs/2026-10-20-edgepulse-design.md)

## 1. 平面与角色

EdgePulse 分两个平面：

- 控制面：浏览器管理后台，负责登录、权限、节点/设备、遥测、告警、固件、命令、审计与系统管理。
- 数据面：边缘节点上的 `edgepulse-agent`，负责 mTLS 注册、心跳、遥测上报、命令执行与固件下载。

P0 交付控制面的认证与节点纵向切片，以及数据面的注册/心跳探针。角色模型在数据库里保留超级管理员、运维管理员、只读观察者三类；P0 只落超级管理员种子。

## 2. 模块与依赖

```text
App
 ├─ Web         HTTP 原语、静态站点、WebSocket 端点、请求标识、安全头
 ├─ Auth        验证码、登录、会话、权限、登录审计 ──> System
 ├─ System      用户、角色、菜单、SQL 迁移
 ├─ Device      节点、Agent 注册表 ──> Web（状态发布经 App 注入）
 └─ Common      响应、分页、密码、随机数、环境变量、数据库封装

依赖方向只向下：App → 业务模块 → Common；System 不依赖 Web/Auth。
Auth 读 System 的用户与菜单；Device 通过 App 注入的访问回调取权限，不直接依赖 Auth。
```

模块边界：

- `Common`：`ApiResponse`、`Pagination`、`PasswordHash`、`RandomBytes/RandomToken`、`IdGenerator`、`Environment`、`Database`（SQLite 连接池 + AsyncExecutor）。
- `System`：`MigrationRunner`（版本表 + SHA-256 校验和）、`UserRepository`、`MenuRepository`。
- `Auth`：`CaptchaService`（内存、2 分钟、一次性、按 IP 限流）、`SessionStore`（不透明 token、2 小时滑动）、`AuthService`、`LoginAudit`、HTTP 控制器。
- `Device`：`NodeRepository`（乐观锁）、`NodeService`、`AgentRegistry`（指纹白名单 + 发布回调）、节点/Agent 控制器。
- `Web`：安全响应头与异常兜底、Bearer 解析、浏览器 WebSocket（首条认证 + 5 秒兜底 + 节点主题扇出）。
- `App`：配置、日志、迁移、监听器装配、服务生命周期与信号停机。

## 3. 监听器与协议

| 端口 | 协议 | 路由范围 |
|---|---|---|
| 8080/TCP | HTTP/1.1 | 健康、认证、节点、WebSocket、API 404 |
| 8443/TCP | HTTPS，ALPN h2/http1.1 | 同上；Alt-Svc 通告 8443/UDP |
| 8443/UDP | HTTP/3 | 同上 + `/api/probe/h3`（只在 h3 路由器上存在） |
| 9443/TCP | HTTPS + mTLS | 只挂 Agent 注册/心跳 |
| 9100/TCP | HTTP/1.1，仅 127.0.0.1 | `/metrics`、`/healthz`、`/readyz`、`/debug/*`；Bearer 保护指标与调试 |

h3 的判定不依赖客户端自报：`/api/probe/h3` 只注册在 QUIC 路由器上，H3Probe 走 h3 得 200；同一路径走 TCP 落到兜底 404。这样“回落 TCP”不会被误判成 h3。

## 4. 认证与会话

登录链路：

```text
captcha(uuid, code) -> login(username, password, captcha, uuid)
  -> 验证码一次性消费
  -> 用户存在且启用
  -> PBKDF2-HMAC-SHA256 校验（工作线程，210000 次）
  -> 角色/权限读取
  -> 生成 32 字节不透明 token（进程内会话，TTL 7200 秒）
  -> 更新 last_login_time
  -> 写 sys_login_log
```

- 口令格式：`pbkdf2_sha256$210000$<salt_b64>$<hash_b64>`，16 字节盐、32 字节输出；比较用恒定时间。
- 会话每次有效访问滑动续期 2 小时；登出立即删除。
- 浏览器只把 token 放在 `Authorization: Bearer` 与 WebSocket 首条认证消息里；URL 永不携带长期 token。
- 验证码按 IP 每分钟 30 次签发上限；登录不另设失败计数（P1 接 Redis）。
- 开发档返回 `{uuid, imageSvg, code}`；生产档只返回 `{uuid, imageSvg}`。

## 5. 数据模型

P0 表：

- `sys_user`、`sys_role`、`sys_menu`、`sys_user_role`、`sys_role_menu`、`sys_login_log`
- `biz_node`
- `schema_migrations`（版本、说明、SHA-256、应用时间）

关键约束：

- `sys_user.username`、`sys_role.role_code`、`biz_node.name` 唯一。
- 节点软删除（`deleted=1`）；所有列表查询带 `deleted=0`。
- `biz_node.version` 做乐观锁；更新影响行数为 0 时区分 404 与 409。
- 时间列用 `DATETIME`；ID 由应用生成（毫秒 << 20 | 序列），不依赖 MySQL/SQLite 自增语法。
- 迁移文件按 `V<数字>__<说明>.sql` 排序；已应用版本校验和不一致时拒绝启动。

## 6. 实时与事件

- 节点状态：Agent 注册/心跳更新 `biz_node` 后，`AgentRegistry` 调用发布回调；App 把节点 JSON 发布到进程内 `WebSocketHub` 的 `nodes` 主题。
- 浏览器 `/api/ws`：升级后 5 秒内必须发 `{"type":"auth","token":"..."}`；成功回 `{"type":"auth","ok":true}` 并订阅 `nodes`；之后所有出站由 Hub 写入。
- 浏览器每 25 秒发 `{"type":"ping"}` 保活；服务端读取入站帧并忽略内容。
- Origin：白名单来自 `edgepulse.security.allowed_origins`；空列表时只允许同源；非浏览器客户端可不带 Origin。

## 7. 引擎边界与应用层绕过

引擎固定 `third_party/AsynGyanis` 的 `v4.0.0` tag，不修改。P0 遇到的边界：

| 引擎 v4.0.0 事实 | 应用层处置 |
|---|---|
| 包内没有 `Core/Crypto/Random.h` | `Common/RandomBytes` 直接用 OpenSSL `RAND_bytes/RAND_priv_bytes` |
| `EventLoop` 没有 `currentEventLoop()` | `AuthController/DeviceController` 由 App/测试显式传入循环引用 |
| `HttpClient` 只有 `setHttp3Enabled`，无强制 h3 | h3 专属探针路径 + TCP 同路径 404 双重判定 |
| HTTP 处理器读不到客户端证书指纹 | TLS 层用 CA + `setClientCertificateRequired(true)` 拒绝无证书/陌生 CA；指纹白名单在 Agent 注册时按自报值校验（同一白名单证书持有者可冒充另一指纹，P2 再评估每节点独立 CA） |
| `WebSocketPeer::receive()` 没有超时参数 | 首条认证 5 秒兜底暂用计时线程（`shortcut`），循环上只做投递与关闭 |
| 没有 SPA `index.html` 回退 | P0 浏览器入口使用 Vite 开发服务器；生产静态托管在 P3 前补齐 |
| 没有 SSE 自动心跳 | P2 用 `SseStream::sendComment()` 每 15 秒发一次 |

## 8. 安全

- 安全响应头：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、CSP；HSTS 只在 TLS 连接上。
- 每个写接口都有权限码；节点列表/写入分别要求 `device:node:list` / `device:node:write`；匿名 401、无权限 403。
- 运维口只监听回环；`/metrics` 与调试端点要求 Bearer；令牌只从 `EDGEPULSE_OPS_BEARER_TOKEN` 或未跟踪的 `var/ops-token` 读取。
- 所有口令、token、私钥只从环境变量或未跟踪文件读取；仓库零明文凭据。
- 口令哈希、会话 token、验证码 uuid 使用密码学随机源；日志不打印 Authorization、Cookie、口令、token。
- 数据库错误不把驱动原文回给客户端；统一 envelope 只带中文可操作说明。

## 9. P0 边界与后续

P0 不做：系统管理域完整接口、设备/遥测/告警/固件/命令、SSE、Agent WebSocket、MySQL/Redis 运行时、多 worker、零停机、OTLP、SPA 静态托管、代码生成器、多租户。

P1 起按 [实施计划](superpowers/plans/2026-10-20-edgepulse-p0.md) 之后的阶段推进；数据面的遥测/命令/固件与告警扇出在 P2。
