## 5. 未覆盖风险

- 真实边缘网络的丢包、NAT、证书轮换与 Agent 长时间断线重连。
- 高并发下的连接池饱和、限流桶、内存预算与 WebSocket 背压。
- 生产 MySQL 的跨版本差异与 DDL 隐式提交：本机只在 MySQL 8 容器验证。
- 固件灰度的 A/B 分区、差分下载与本地回滚槽位没有实现；真实跨波次大目标、长时间回滚期限与分组目标未覆盖，`listDueRollouts LIMIT 20` 的积压调度与波次/目标写入的原子性留给 P11。
- 存储层（MySQL/Redis）高可用、跨地域多活与自动分片；控制面双实例已覆盖，但单点存储故障仍会让整个控制面不可用。
- 多实例下租约时钟偏差与网络分区的极端场景：NTP 未对齐或数据库连接半开时可能双 leader，当前只在容器内用停止/崩溃验证接管。
- 浏览器兼容性只验证了系统 Edge。
- Docker 镜像只在 x86_64 Linux 容器验证，多架构构建未覆盖；`edgepulse.service` 只在特权容器验证，`edgepulse@.service` 未在真实 systemd 主机启动。
