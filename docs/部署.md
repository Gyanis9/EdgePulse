# EdgePulse 部署

## 1. 构建与运行产物

```bash
git submodule update --init --recursive
conan create 3rd/AsynGyanis/packaging/conan --build=missing \
  -s compiler.cppstd=23 -s build_type=Release -o "&:with_mysql=True"
conan install . --build=missing -s compiler.cppstd=23 -s build_type=Release
cmake --preset release
cmake --build --preset release --parallel
```

产物：

- `build/release/edgepulse-server`：后端可执行体。
- `frontend/dist`：前端构建产物；`bash scripts/build-web.sh` 会刷新到未跟踪的 `web/`。
- `migrations/`：启动时自动应用；不要手工改已应用文件的校验和。

## 2. 配置与秘密

复制 `config/prod.yaml.example` 为未跟踪的 `config/prod.yaml`，按环境改端口、监听地址、MySQL/Redis 主机与 `web_root`。

秘密只从环境变量读取：

| 变量 | 用途 |
|---|---|
| `EDGEPULSE_DB_PASSWORD` | MySQL 口令 |
| `EDGEPULSE_REDIS_PASSWORD` | Redis 口令 |
| `EDGEPULSE_OPS_BEARER_TOKEN` | 运维口 Bearer |
| `EDGEPULSE_AGENT_FINGERPRINT` | 允许注册的 Agent 证书 SHA-256 |
| `EDGEPULSE_INITIAL_PASSWORD` | 用户表单里的初始口令提示（不落库、不写日志） |
| `EDGEPULSE_UDP_TELEMETRY_SECRET` | UDP 遥测 HMAC 共享密钥；启用 UDP 时必填，至少 16 字节 |
| `EDGEPULSE_OIDC_CLIENT_SECRET` | OIDC 客户端密钥；公共客户端可留空 |

仓库零明文凭据；不要把口令写进 YAML、命令行参数、镜像层或 Git。

## 3. 证书

开发档：

```bash
bash scripts/dev-certs.sh
```

生成 CA、服务器证书、Agent 客户端证书与一组“陌生 CA”证书，放在未跟踪的 `var/certs/`。Agent 指纹写入 `var/certs/agent-fingerprint.txt`。

生产档把证书放到 `cert_dir` 指向的目录，至少需要：

- `server.pem` / `server-key.pem`：8443 与 9443 共用。
- `ca.pem`：Agent 客户端证书的信任锚。

Agent 连接 9443 时必须带客户端证书与私钥；无证书或陌生 CA 在 TLS 握手阶段被拒。

### Agent 注册与证书

Agent 侧配置在 `edgepulse.agent` 下：

```yaml
edgepulse:
  agent:
    fingerprint: ""            # 可选：额外的固定指纹白名单，空表示只依赖 CA 链
    enrollment_mode: required  # off 或 required；生产使用 required
    heartbeat_interval_seconds: 30
    heartbeat_timeout_seconds: 90
    offline_sweep_seconds: 30
```

- `off`：开发档默认。新节点和换证书只靠 mTLS 链校验与指纹，不要求一次性令牌。
- `required`：新节点首次注册必须持 `enroll` 令牌；已有节点更换证书必须持 `rebind` 令牌；同指纹重注册不需要令牌。`enroll` 令牌不能用于已有节点，`rebind` 令牌不能创建新节点，缺令牌或令牌不可用返回 403。
- 令牌有效期必须在 300 到 2592000 秒之间；明文只在签发响应出现一次，列表只返回 `active/used/expired/revoked` 状态。

生产上线步骤：

1. 节点首次注册前，用管理员会话调用 `POST /api/enrollment-tokens`（`action` 为 `enroll`，建议用 `nodeName` 限定该节点），把响应里的 `token` 交给 Agent；Agent 在 `/api/agent/register` 的 `enrollmentToken` 字段带上它。
2. 更换 Agent 证书时先签发 `rebind` 令牌，再用新证书注册；不要复用旧令牌，每枚令牌只能消费一次。
3. 注册成功后 `GET /api/nodes/:id` 可读 `certNotAfter` 与 `certRevokedAt`；吊销证书会清空指纹、把节点置为离线，并以 1008 关闭该节点已建立的 Agent WebSocket 连接。
4. 超过 `heartbeat_timeout_seconds` 没有心跳的在线节点会被置为离线并生成系统离线告警，恢复心跳后自动销案。

## 4. 本地运行

```bash
bash scripts/run-dev.sh
```

脚本会确保证书与 `var/ops-token` 存在，导出运维令牌与 Agent 指纹，然后前台启动 `edgepulse-server --config config/dev.yaml`。

默认端口：8080 HTTP、8443 TCP/UDP、9443 mTLS、9100 运维口；UDP 遥测默认关闭，启用后监听 9555/UDP。详见 [架构](架构.md)。

UDP 遥测在 `config/prod.yaml` 中打开：

```yaml
edgepulse:
  udp_telemetry:
    enabled: true
    address: 0.0.0.0
    port: 9555
```

并设置 `EDGEPULSE_UDP_TELEMETRY_SECRET`（至少 16 字节）。数据报格式与签名算法见 [API](API.md) 的 UDP 遥测一节；Compose 已映射 9555/UDP 并把该环境变量透传进容器。

OIDC 登录在 `config/prod.yaml` 中按需打开：

```yaml
edgepulse:
  oidc:
    enabled: true
    issuer: https://idp.example.com
    client_id: edgepulse
    redirect_uri: https://console.example.com/api/auth/oidc/callback
    frontend_redirect: /login
    scopes: openid profile email
    allowed_email_domains: example.com
    auto_provision: true
    default_role_id: 2
    default_dept_id: 101
    tenant_code: default
```

`tenant_code` 决定 OIDC 外部身份落到哪个租户；外部账号只在该租户内按邮箱匹配或自动创建。租户由平台管理员在“系统管理 → 租户管理”创建，默认租户编码 `default` 承接升级前数据。

并在 IdP 侧登记同一个 `redirect_uri`；`issuer` 与 `redirect_uri` 必须是 HTTPS 或本机回环。Compose 已把 `EDGEPULSE_OIDC_CLIENT_SECRET` 透传进容器。

边缘反向代理在 `config/prod.yaml` 中按需打开：

```yaml
edgepulse:
  reverse_proxy:
    enabled: true
    prefix: /edge
    upstream: http://device-api:9000
    strip_prefix: true
    require_session: true
    permission: ""
```

它只转发 HTTP 请求/响应，不透传 EdgePulse 的 Authorization/Cookie，也不代理 WebSocket 升级与大流式响应。

## 5. 生产环境

最小拓扑：

- 一台或多台 EdgePulse 实例，挂同一个 MySQL；跨实例会话与验证码需要 Redis。
- MySQL 8.x 建库 `edgepulse`，用户 `edgepulse` 只需该库的 DML/DDL 权限。
- Redis 7.x 用来放会话、验证码与登录失败计数；启用时 `edgepulse.redis.enabled=true`。
- 反向代理/负载均衡负责 TLS 卸载时，后端仍建议保留 8443/9443 的 TLS 入口；Agent 必须直连 mTLS 端口。

启动顺序：

1. 数据库可连接、迁移目录可读。
2. 若启用 Redis，Redis 可连接；连接失败时启动失败而不是静默退化成内存。
3. 服务器证书、私钥与 CA 可读。
4. `/readyz` 返回 200 后再接入流量。

### Webhook 出站安全（SSRF）

告警 Webhook 由租户管理员填写，服务端在创建或修改渠道时解析主机并逐个检查地址：

- 默认拒绝回环、私网、CGNAT、组播、保留与文档示例段，以及 IPv6 回环、唯一本地、组播、文档段和 IPv4-mapped IPv6。
- `localhost`、`*.localhost` 与 `*.local` 这类本机或局域网别名默认拒绝；打开开关后交给解析器，解析结果仍按地址段检查。
- 云元数据地址与主机名（如 `169.254.169.254`、`169.254.170.2`、`100.100.100.200`、`fd00:ec2::254`、`fd20:ce::254`、`metadata.google.internal`、`instance-data`、`metadata.tencentyun.com`）始终拒绝，不受下面的开关影响。
- 整个 IPv4 链路本地段 `169.254.0.0/16` 与 IPv6 链路本地段 `fe80::/10` 也始终拒绝：云元数据端点都落在这两段里，不能靠枚举已知端点来兜底。
- 每次投递前还会复检一次；命中上述地址时不发请求，只记一条失败投递并累加 `edgepulse_webhook_ssrf_rejections_total`。

自建内网网关（例如 `http://10.0.0.8/hook`）需要在 `config/prod.yaml` 显式打开：

```yaml
edgepulse:
  security:
    allow_private_webhooks: true
```

默认是 `false`。该开关只放行普通的 RFC1918 私网与回环地址，不放行云元数据主机名、元数据 IP 或任何链路本地地址。开发档 `config/dev.yaml` 为本地验收 Webhook 打开了它。

校验与实际连接之间存在 DNS 重绑定窗口：引擎客户端会再次解析域名，可能拿到与校验时不同的地址。高安全环境不要只依赖这个开关，应在主机或容器网络层配置出站防火墙与域名白名单。

反向代理的 upstream 是运维配置，只校验协议与 userinfo，不受本节的私网限制。

### 口令策略、登录锁定与全局限流

建号、管理员重置与用户改密共用同一套口令策略，配置在 `edgepulse.security` 下：

```yaml
edgepulse:
  security:
    password_min_length: 10          # 8 到 64；6 位仅保留给旧测试策略
    password_require_complexity: true # 要求同时包含大写、小写、数字与符号
    login_failure_window_seconds: 900 # 60 到 86400
    login_max_failures: 5             # 1 到 100
    login_lock_seconds: 900           # 60 到 86400
```

生产档用 10 位加复杂度；开发档 `config/dev.yaml` 放宽为 8 位且不要求复杂度，历史种子账号与本地验收脚本因此无需改口令。策略只约束新建、重置与修改，既有账号仍可用原口令登录。

登录失败先按来源 IP 限频，再按账号累计：窗口内连续失败达到 `login_max_failures` 后写入锁定截止时刻，触发锁定的那次失败仍返回统一的 401，下一次尝试起返回 423 并提示等待分钟数。该账号在任何 IP 上用正确口令也会被锁定挡住；管理员重置口令会同时清空失败计数与锁定。成功登录会清空账号与 IP 两侧的失败计数。

连接与限流配置在顶层 `server` 下，全部在启动时生效，热重载不会改变：

```yaml
server:
  limits:
    idle_timeout_ms: 75000    # 两次请求之间的空闲；0 关闭
    read_timeout_ms: 60000    # 相邻两次读取的最长间隔；0 关闭
    write_timeout_ms: 60000   # 处理器与发送响应的时限；0 关闭
  parser_limits:
    maximum_body_size: 16777216
  rate_limit:
    requests_per_second: 0.0  # 可为小数；0 关闭全局限流
    burst_capacity: 1.0       # 令牌桶容量，必须不小于 1
```

`server.limits.read_timeout_ms` 与 `write_timeout_ms` 作用于 HTTP、HTTPS、Agent、运维口与 h3 监听器，`idle_timeout_ms` 只对 HTTP、HTTPS、Agent 与运维口生效。h3 的空闲计时由 QUIC 传输层的 `Configuration::idleTimeout` 决定（当前使用引擎默认 30 秒），不读 `HttpServerLimits::idleTimeout`，因此调大 `idle_timeout_ms` 不会延长 h3 连接。

`server.parser_limits.maximum_body_size` 是 Agent 与运维口的正文上限，这两类监听器只收心跳、状态与指标等小正文。公开 HTTP、HTTPS 与 h3 接受固件上传，解析上限取 `maximum_body_size` 与 `edgepulse.maximum_firmware_bytes` 的较大者，启动日志会打印两类监听器各自生效的字节数。`requests_per_second` 按浮点读取，请写成 `10.0` 这类带小数点的形式（整数会被当成未配置并回落到 0）；大于 0 时 HTTP、HTTPS 与 h3 共用同一个令牌桶，超速请求返回 429 与 `Retry-After`，设为 0 则不注册限流中间件。生产环境建议按实例容量设置非零值，并让 `burst_capacity` 覆盖正常的并发突发。

## 7. Docker

构建镜像：

```bash
docker build -f deploy/docker/Dockerfile -t edgepulse:ci .
```

受限网络可换源（apt 与 Node 基础镜像）：

```bash
docker build -f deploy/docker/Dockerfile -t edgepulse:ci .   --build-arg APT_MIRROR=mirrors.aliyun.com/ubuntu   --build-arg NODE_IMAGE=<可访问的 node:22-bookworm 镜像>
```

Compose 提供 MySQL、Redis、EdgePulse 与 Prometheus：

```bash
cd deploy/docker
cp .env.example .env
# 设置 MYSQL_ROOT_PASSWORD、EDGEPULSE_DB_PASSWORD、
# EDGEPULSE_REDIS_PASSWORD、EDGEPULSE_OPS_BEARER_TOKEN
# 把同一个运维令牌写进 deploy/prometheus/ops-token
bash ../../scripts/dev-certs.sh   # 或放置生产证书到 var/certs
docker compose up -d
```

注意：

- `.env`、`deploy/prometheus/ops-token`、`config/prod.yaml` 与证书都不进版本库，且都在 `.dockerignore` 中，不会进入构建上下文。
- Compose 把 `../../config` 只读挂到 `/app/config`；缺少 `prod.yaml` 时入口脚本把样例复制到 `/var/lib/edgepulse/prod.yaml` 再启动，不往挂载里写。
- `ops_address` 必须是 `0.0.0.0`，否则 Prometheus 容器抓不到 `edgepulse:9100/metrics`；该口仍需 Bearer。
- 运行镜像已预建 `/app/var/logs`，默认 `logging.yaml` 可写；前端产物、迁移与配置都在镜像内。
- 全栈验收：`python scripts/check-docker-stack.py --build`（复用镜像时去掉 `--build`）。脚本会自备随机秘密、证书与测试配置，覆盖登录、自定义角色、节点、审计落库、Redis 会话跨重启、Prometheus 抓取、真实 OTel collector 与 SIGTERM 优雅停机，结束后只清理本项目的容器与卷。
- 受限网络下镜像拉取失败时，用 `EDGEPULSE_DOCKER_NODE_IMAGE` 与 `EDGEPULSE_DOCKER_APT_MIRROR` 覆盖 Node 基础镜像与 apt 源，脚本会把它们转成 `--build-arg`。
- 验证包含 V1–V14 迁移与 `sys_tenant` 种子；租户隔离在 SQLite 集成/协议用例中覆盖，MySQL 档验证迁移与默认租户落库。
- 本机已在 Docker 中验证 MySQL 8.4、Redis 7、Prometheus 与 OTel collector 全栈；镜像内二进制经 `ldd` 检查无缺失依赖。

## 8. systemd

`deploy/systemd/edgepulse.service` 是单实例模板：

1. 二进制放 `/opt/edgepulse/edgepulse-server`，前端产物放 `/opt/edgepulse/web`，迁移放 `/opt/edgepulse/migrations`。
2. 配置放 `/etc/edgepulse/config.yaml`，秘密放 `/etc/edgepulse/edgepulse.env`（0600）。
3. `systemctl daemon-reload && systemctl enable --now edgepulse`。
4. 用 `curl http://127.0.0.1:9100/readyz` 判断就绪；`journalctl -u edgepulse -f` 看日志。

单元文件启用了 `ProtectSystem=strict`、`NoNewPrivileges` 与只写 `/var/lib/edgepulse`，固件目录必须在可写路径内。配置目录若放 `logging.yaml`，文件日志的 `directory` 要用绝对路径（如 `/var/lib/edgepulse/logs`），否则日志只进 journal。

本机已在一个特权 systemd 容器中真机启动该单元：服务进入 `active`、`/readyz` 返回 ready、`systemctl stop` 后 `ExecMainCode=1` 且 `ExecMainStatus=0`。真实主机上的内核与 cgroup 差异仍需在目标发行版复核。

## 9. Prometheus 与 OTLP

- Prometheus 抓取 `edgepulse:9100/metrics`，Bearer 从 `credentials_file` 读取；样例见 `deploy/prometheus/prometheus.yml`。
- `/metrics` 输出引擎 `asyn_http_*` 与业务 `edgepulse_build_info`；`/api/ops/summary` 给业务读数。
- 要推 OTLP，在配置里把 `metrics.enabled` 设为 true，并填 `metrics.service_name` 与 `metrics.otlp.endpoint`；`scripts/check-otlp.py` 用 mock collector、`scripts/check-docker-stack.py` 用真实 OTel collector 容器验证送达，外部生产采集端的网络与鉴权需在部署环境验证。

## 10. 热重载、就绪与停机

- `edgepulse.hot_reload=true` 时监听配置目录；会话 TTL、验证码 TTL/限流热生效，监听地址与端口需重启。
- `/readyz` 依赖数据库探针与就绪标志；收到停机请求先返回 503，再按 HTTP/HTTPS/mTLS/QUIC/Ops 顺序排空，最后停止事件循环。
- 滚动发布时先摘流量、等 `/readyz` 变 503，再发停止信号；新实例就绪后再接回流量。单机没有监听句柄交接，零 5xx 依赖负载均衡的滚动机型。

## 11. 备份与恢复

- MySQL：按库做物理/逻辑备份；`schema_migrations` 必须与迁移文件一起保留，否则启动时校验和会对不上。
- SQLite：停机后复制 `var/edgepulse.db`；运行中复制可能拿到不一致快照。
- 固件：备份 `firmware_dir`；数据库只存元数据，文件丢失会导致下载 404。
- 证书与运维令牌单独托管，不要和数据库备份放同一份未加密介质。

## 12. 固件签名

固件签名覆盖文件 SHA-256 的 32 字节原始摘要，算法标识为 `ed25519-sha256`，签名字节以标准 Base64 传输。上传时服务端验签，下载时把 `X-Firmware-Signature`、`X-Firmware-Key-Id`、`X-Firmware-Signature-Algorithm` 回给 Agent，Agent 可据此复核落盘文件。

1. 生成密钥对：`bash scripts/firmware-signing-keygen.sh prod-2026`。私钥写在未跟踪的 `var/firmware-signing-key.pem`，脚本拒绝覆盖已有私钥或同名公钥；key id 只允许字母、数字、点、下划线与连字符，不能含路径分隔符或 `..`。公钥写到 `config/firmware-keys/prod-2026.pem`。
2. 只把公钥分发到各实例的 `edgepulse.firmware.trusted_keys_dir`；私钥留在签名工作站或密钥管理系统，不进入镜像、备份与仓库。
3. 对固件签名：`bash scripts/sign-firmware.sh var/firmware-signing-key.pem <固件> prod-2026`，输出 `key=` 与 `signature=` 两行。
4. 上传时带两个请求头：`X-Firmware-Signature: <signature>` 与 `X-Firmware-Key-Id: prod-2026`。缺签名或缺 key id 的请求在收正文前就返回 400，不会写盘；只有写完文件后才做的验签（key 不受信任、摘要不符、签名格式不对）失败时返回 400，并删除已写入的成品。
5. 切换门禁：把 `edgepulse.firmware.require_signature` 改为 `true` 并重启。生产样例默认开启，且信任键目录为空时启动直接失败；目录要求写绝对路径。
6. 开启后未签名固件不能上传、部署或回滚，但已入库的历史未签名固件仍可被 Agent 下载。需要继续下发这些旧固件时，先重新上传带签名的同版本固件，再按新记录部署。
7. `GET /api/firmware/policy` 需要权限 `device:firmware:list`，返回 `{requireSignature, trustedKeyIds}`，用于确认当前实例加载了哪些公钥。
