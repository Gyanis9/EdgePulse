# EdgePulse 部署（P0）

- 版本：P0（2026-10-20）
- 适用：Windows 开发档与单进程 Linux 验证；多 worker/容器/systemd 在 P3 补齐

## 1. 前置条件

- Windows + MSVC ≥ 19.40，或 Linux + GCC ≥ 13 / Clang ≥ 17
- CMake ≥ 3.25、Ninja、Conan 2、Python 3、Node.js ≥ 20、OpenSSL
- Git（含 submodule）

引擎固定在 `third_party/AsynGyanis` 的 `v4.0.0` tag，只读，不修改、不复制、不用 `add_subdirectory`。

## 2. 构建

```bash
git submodule update --init --recursive

conan create third_party/AsynGyanis/packaging/conan --build=missing \
  -s compiler.cppstd=23 -s build_type=Release -o "&:with_mysql=True"

conan install . --build=missing -s compiler.cppstd=23 -s build_type=Release
cmake --preset debug
cmake --build --preset debug
ctest --preset debug --output-on-failure
```

`debug` 预设实际是 RelWithDebInfo + `/MD`，目的是与 Release 引擎包保持同一 CRT；不要改成 `/MDd`，否则链接期报 LNK2038。`-o "&:with_mysql=True"` 会现场编译 libmysqlclient；P0 运行时仍用 SQLite。

前端：

```bash
cd frontend
npm ci
npm run build
```

## 3. 证书与秘密

```bash
bash scripts/dev-certs.sh
```

在 `var/certs` 生成（未跟踪）：

- `ca.pem` / `ca-key.pem`：开发 CA（带 CA:TRUE 与 keyUsage）
- `server.pem` / `server-key.pem`：SAN `DNS:localhost, IP:127.0.0.1`
- `agent.pem` / `agent-key.pem`：Agent 客户端证书
- `agent-foreign.pem` / `agent-foreign-key.pem`：同 CA、用于对照的证书
- `agent-fingerprint.txt`：`agent.pem` 的 SHA-256 小写指纹

外部 Agent 证书：

```bash
bash scripts/gen-agent-certs.sh my-edge-node
```

秘密只从环境变量或未跟踪文件读取：

| 变量/文件 | 用途 |
|---|---|
| `EDGEPULSE_OPS_BEARER_TOKEN` 或 `var/ops-token` | 9100 `/metrics` 与调试端点 Bearer |
| `EDGEPULSE_AGENT_FINGERPRINT` 或 `var/certs/agent-fingerprint.txt` | Agent 注册指纹白名单 |
| `EDGEPULSE_DB_PASSWORD` | MySQL 生产配置（P1） |

`run-dev.sh` 会生成缺失的 `var/ops-token` 并导出上述环境变量。

## 4. 运行

```bash
bash scripts/run-dev.sh
```

等价于：

```bash
EDGEPULSE_OPS_BEARER_TOKEN="$(cat var/ops-token)" \
EDGEPULSE_AGENT_FINGERPRINT="$(cat var/certs/agent-fingerprint.txt)" \
./build/debug/edgepulse-server --config config/dev.yaml
```

监听：

| 端口 | 用途 | 暴露面 |
|---|---|---|
| 8080/TCP | HTTP + WebSocket | 开发档 `127.0.0.1` |
| 8443/TCP | HTTPS/h2 | 控制台 |
| 8443/UDP | HTTP/3 | 控制台 |
| 9443/TCP | Agent mTLS | 数据面 |
| 9100/TCP | 运维 | 仅 `127.0.0.1` |

开发种子账号 `admin` / `admin123`；生产部署必须在首次登录后改密。

## 5. 数据

- 开发档 SQLite：`var/edgepulse.db`，启动时自动应用 `migrations/V1–V3`。
- 迁移版本表 `schema_migrations` 记录 SHA-256；修改已应用文件会拒绝启动。
- 重置开发数据：停止服务，删除 `var/edgepulse.db`，重启即可重新建表与种子。
- 生产 MySQL 与 Redis 会话在 P1 接入；P0 不做第二套运行配置。

## 6. 运维

```bash
TOKEN="$(cat var/ops-token)"
curl -H "Authorization: Bearer ${TOKEN}" http://127.0.0.1:9100/metrics
curl http://127.0.0.1:9100/healthz
curl http://127.0.0.1:9100/readyz
```

Prometheus 抓取样例在 `deploy/prometheus/scrape.yml`。`/metrics` 含引擎进程指标与 HTTP 统计；业务节点计数在 P3 接 `ProcessMetricsRegistry` 后再补。

## 7. 协议验收

```bash
python scripts/check-acceptance.py
```

脚本会按需启动开发服务并逐项检查认证、节点、h3、mTLS、WebSocket 与 metrics。

## 8. 常见问题

- **curl 访问 8443 报 `schannel: revocation status is unknown`**：Windows 自签 CA 没有吊销信息，用 `curl --ssl-no-revoke --cacert var/certs/ca.pem`；或直接用 H3Probe/AgentProbe（OpenSSL）。
- **9443 无证书报连接被中止**：这是 mTLS 预期行为。
- **h3 探针失败但 HTTPS 正常**：检查 8443/UDP 是否被本机防火墙拦住；H3Probe 必须打印 `h3` 才算通过，TCP 404 回落不算。
- **服务启动报缺少证书**：先运行 `bash scripts/dev-certs.sh`。
- **服务启动报缺少运维令牌**：运行 `bash scripts/run-dev.sh`，或设置 `EDGEPULSE_OPS_BEARER_TOKEN` / 写入 `var/ops-token`。
- **修改旧迁移后启动失败**：这是校验和保护；新增一版迁移，不要改已应用文件。

## 9. P0 未覆盖

多 worker、优雅换代、systemd notify/watchdog、Docker 镜像、MySQL/Redis 生产运行时、SPA 静态托管、OTLP、SSE 与 Agent WebSocket 属于后续阶段；P0 的容器与 systemd 文件只是未验收样例。
