# EdgePulse 验收

## 1. 验收命令

```bash
# 后端
ctest --preset debug --output-on-failure

# 前端
cd frontend
npm run test:unit
npm run build
npm run test:e2e

# 协议与安全（按需启动开发服务）
python scripts/check-acceptance.py
```

`scripts/check-acceptance.py` 会优先复用已在 8080 运行的服务；没有时用 `scripts/run-dev.sh` 启动，结束后只停止自己启动的进程。

- Agent 身份绑定后，遥测、命令、固件下载与配置检查都使用 `POST /api/agent/register` 返回的节点，不再复用手工创建的管理节点。
- 脚本结束时删除本次运行创建的 `accept-node-<run>`、`edgepulse-agent-http-<run>` 与 `ws-agent-<run>` 节点，并先恢复这些节点上未恢复的告警；mTLS 样例注册的固定节点 `edgepulse-agent` 跨次复用，不删除。
- 离线检查会故意让 Agent 节点超时离线，等待 `heartbeat_timeout_seconds + offline_sweep_seconds + 10` 秒（开发档 30/5，上限 45 秒），放在全部检查的最后。
- 固件签名检查需要在服务启动前把临时公钥放进信任键目录，因此只在脚本自己启动服务时执行；复用已运行服务、缺少 openssl，或 `config/firmware-keys/acceptance.pem` 已存在（不覆盖非本次生成的公钥）时打印 `SKIP`。`SKIP` 不计入通过，也不让退出码变成失败。
- 任一项 `FAIL` 以非零退出码结束；汇总行同时给出通过、失败与跳过数量，不能把非零退出当作通过。

## 2. 覆盖项

### 2.1 认证与系统管理

- 验证码签发、开发档 code、管理员登录、`x-request-id`。
- `me` 返回角色与权限，`routes` 返回设备菜单。
- 用户、角色、菜单、部门、岗位、字典、参数列表可读。
- 创建角色与用户，低权限账号访问用户管理返回 403。
- 操作日志统计、登录日志统计、工作台汇总可读。
- 操作审计落库：系统写操作可在 `/api/monitor/oper-logs` 查到。
- 租户：平台管理员创建租户并生成根部门与租户管理员角色；租户管理员按编码登录，`me` 带租户身份；本租户账号可见、默认租户账号不可见；租户可自建角色/部门/岗位/字典且不能授予自己没有的菜单；停用租户后新登录与被签发的旧会话都被拒。
- 通知渠道：Webhook 收到告警 JSON 且 HMAC 签名匹配；SMTP 假服务器收到带主题与收件人的邮件。

### 2.2 节点、注册令牌、遥测与告警

- 创建节点并在列表读回；节点分组可读。手工节点只用于列表检查，不承担 Agent 身份，运行结束时删除。
- 注册令牌：签发 `enroll` 令牌的响应带明文 `token` 且以 `ep_enroll_` 开头；列表返回数组，任何行都不含 `token` 或 `tokenHash`；吊销返回 200。
- Agent 通过 mTLS 注册后用返回的节点标识上报遥测；CPU 越过阈值后 2 秒内可在告警列表读到。
- 遥测最新值与时间序列可读。
- 用 `agent-foreign.pem`/`agent-foreign-key.pem` 冒用该节点心跳返回 403，证明心跳通道按连接叶证书与登记指纹做身份绑定；除 `/api/agent/register` 外的其余 `/api/agent/*` 路由的同类校验由单元与集成用例覆盖，不由这一条心跳单独证明。
- 配置下发：管理端以 `expectedVersion=0` 写入配置，期望版本变为 1；Agent 拉取到版本 1 与同一正文，回报 `applied` 后管理端 `inSync=true`；心跳响应带 `desiredConfigVersion=1`。
- SSE `/api/events/alarms` 建立后收到 `ready`，随后 3 秒内收到 `alarm` 事件。
- 告警确认与恢复接口可用，规则列表包含种子规则。
- 离线生命周期：发送一次心跳后等待最多 45 秒，节点状态变为 `offline` 且出现 `metric=node.online` 的系统告警；再发心跳后节点回到 `online`，该告警变为 `resolved`。这一项放在最后执行。

### 2.3 命令与固件

- 浏览器创建命令；Agent 轮询取到并置 running；回传结果后状态为 succeeded。
- Agent 示例以 `--ws` 建立 mTLS WebSocket，完成 hello 后由长连接收到推送命令并回写结果，命令状态为 succeeded。
- 100 MiB 固件流式上传，服务端字节数与 SHA-256 与客户端计算一致。
- Range `bytes=0-1023` 返回 206 与正确 `Content-Range`，请求带 `nodeId` 且节点与连接证书一致。
- 携带 ETag 的 `If-None-Match` 返回 304，同样带 `nodeId`。
- 固件下发给 Agent 注册节点，任务列表可读；下载与任务归属都按该节点校验。
- 签名固件（可选）：脚本自己启动服务时生成临时 Ed25519 密钥，把公钥写入 `config/firmware-keys/acceptance.pem`，对小型固件摘要签名后带 `X-Firmware-Signature`/`X-Firmware-Key-Id` 上传，断言响应 `signed=true`、下载回传三个签名头；结束后删除本次生成的私钥、公钥与固件记录。复用已运行服务或缺少 openssl 时打印 `SKIP`，不计入通过。开发档 `require_signature=false`，因此该检查验证的是「带签名的上传会验签并落元数据」，不是强制门禁本身。

### 2.4 协议与安全

- 8443 HTTPS 健康检查；`/api/probe/h3` 走 TCP 为 404。
- H3Probe 真实 h3 返回 200 且输出 h3。
- 9443 无客户端证书被拒；正确客户端证书注册、心跳与 HTTP 注册通过；同一 CA 签发的陌生证书冒名心跳返回 403。
- 浏览器 WebSocket 首条消息认证成功。
- Webhook 元数据地址 `http://169.254.169.254/latest/meta-data` 在开发档 `allow_private_webhooks=true` 下仍返回 400，错误文案含「元数据」。
- 9100 `/metrics` 无令牌 401、带令牌 200；`/readyz` 与 `/healthz` 200。
- 账户锁定、口令策略与全局限流不在验收脚本里重复造并发；由 GoogleTest 的认证与限流用例覆盖，验收脚本保留登录 401/403 与租户隔离路径。
- `scripts/check-otlp.py` 启动 mock collector 与独立端口的服务，断言收到 `POST /v1/metrics`、`Content-Type: application/json`，且正文含指标名。

### 2.5 容器与进程管理

- Dockerfile 构建出可运行的 `edgepulse:ci` 镜像，二进制无缺失动态库，前端与 V1–V18 迁移都在镜像内。
- Compose 启动 MySQL 8.4、Redis 7、Prometheus、真实 OTel collector 与 EdgePulse；`/api/health`、`/readyz`、带令牌的 `/metrics` 均可读。
- MySQL 档完成登录、CUSTOM 角色与部门写读、节点创建与查询、审计落库；`schema_migrations` 覆盖 V1–V18，`sys_tenant` 含默认租户，`sys_role_dept` 与 `biz_node` 行数符合预期。
- Redis 中存在 `edgepulse:session:*`；重启 EdgePulse 容器后原会话仍可访问 `/api/auth/me`。
- OTel collector 收到 EdgePulse 指标；Prometheus 的 `edgepulse` 抓取目标为 up。
- UDP 遥测：独立端口的服务收到 HMAC 签名数据报，返回 `accepted`，遥测最新值可回读；重放与坏签名被拒。
- 边缘反代：真实上游服务验证方法、前缀剥离、查询、正文、状态码与响应头转发；匿名请求按配置被 401，超大正文被 413。
- OIDC：mock IdP 走完授权码 + PKCE，ID Token 通过 RS256 校验，一次性 code 换会话、重放被拒，自动建号落库。
- `docker stop` 后容器退出码为 0，SIGTERM 走完优雅停机。
- systemd 特权容器中服务为 `active`，`/readyz` 为 ready，`systemctl stop` 后 `ExecMainCode=1`、`ExecMainStatus=0`。

## 3. 结果判定

- 后端、前端与各脚本的通过数量以当次实际运行输出为准；本文只描述检查结构，不预写数量。
- `scripts/check-acceptance.py` 逐项打印 `PASS`/`FAIL`，条件无法构造时打印 `SKIP`；`ctest` 用例用 GoogleTest 的 `SKIP`。`check-docker-stack.py`、`check-otlp.py`、`check-oidc.py`、`check-udp-telemetry.py` 等脚本按各自的成功/失败输出报告，既不打印逐项 `SKIP`，也不汇总通过、失败与跳过数量；只有 `check-acceptance.py` 在末尾汇总这三类计数。任一项 `FAIL` 以非零退出码结束，非零退出不能当作通过。
- `SKIP` 只用于本次无法构造的条件：`check-acceptance.py` 在复用已运行服务、缺少 openssl 或临时公钥已存在时跳过固件签名检查；`ExternalStores.*`、`RealtimeBus.*` 在缺少真实 MySQL/Redis 环境变量时由 GoogleTest 跳过。跳过不计入通过，也不掩盖失败。这三项已有可复现的真机路径：`scripts/run-external-tests.py` 起一次性容器后断言三项全部执行，CI 的 Linux 后端任务用 MySQL 8.4/Redis 7 service 跑同一组并检查输出不含 Skipped。
- 验收结论以脚本实际输出为准；环境门控的历史结果只作参考，不在文档里替代本次运行。

## 4. 设计性限制的验收口径

- SQLite 与内存档是默认路径；真实 MySQL/Redis 由 `EDGEPULSE_TEST_MYSQL_*` 与 `EDGEPULSE_TEST_REDIS_*` 门控，缺依赖即 SKIP，不伪造通过。`scripts/run-external-tests.py` 起一次性容器后三项全部通过，覆盖迁移与新增列、日志数据范围列、KV 操作与双实例扇出；CI 用 service 容器跑同一组。MySQL 备份与恢复往返由 `scripts/backup_restore_mysql_test.py` 在一次性容器中验证。
- OTLP 已用本地 mock collector 验证真实送达；外部生产采集端的网络与鉴权不在本机验收范围。
- Docker 镜像与 Compose 全栈已真机验证；systemd 在特权容器中验证，真实主机内核与 cgroup 差异未覆盖。
- 外部生产 OTLP 采集端未接入；本地已用真实 collector 容器验证协议与送达。
- 多进程编排不在本次默认运行形态；P4 的 UDP 遥测、反代、OIDC 与多租户均已纳入验收；P5 的证书身份绑定、注册令牌、离线生命周期、设备影子、固件签名、Webhook SSRF、账户锁定与限流由 GoogleTest 或验收脚本分别覆盖。
- 多实例共享 MySQL 时离线扫描、保留期清理与指标刷新会在每个实例各跑一遍，默认单实例运行形态；没有选主，验收不声称多实例单飞。

## 5. 真机存储用例

可复现路径是在仓库根运行：

```bash
python scripts/run-external-tests.py            # 默认 mysql:8.4 与 redis:7
python scripts/run-external-tests.py --redis-image redis:7-alpine
```

脚本启动只绑定 127.0.0.1 随机宿主端口的一次性容器，口令每次随机生成，注入 `EDGEPULSE_TEST_MYSQL_*` 与 `EDGEPULSE_TEST_REDIS_*` 后运行 `ctest -R "ExternalStores|RealtimeBus"`；`--no-tests=error` 与输出计数校验保证三项用例确实执行，正常结束即清理容器，`--keep` 只在失败时保留现场。CI 的 Linux 后端任务用 MySQL 8.4/Redis 7 service 注入同一组变量，并在测试后单独断言输出不含 Skipped。

也可以自行准备 MySQL/Redis 后手动注入变量：

```bash
EDGEPULSE_TEST_MYSQL_HOST=127.0.0.1 EDGEPULSE_TEST_MYSQL_PORT=3306 \
EDGEPULSE_TEST_MYSQL_USER=root EDGEPULSE_TEST_MYSQL_PASSWORD=... \
EDGEPULSE_TEST_MYSQL_DATABASE=edgepulse_test \
EDGEPULSE_TEST_REDIS_HOST=127.0.0.1 EDGEPULSE_TEST_REDIS_PORT=6379 \
EDGEPULSE_TEST_REDIS_PASSWORD=... \
ctest --preset debug -R "ExternalStores|RealtimeBus" --output-on-failure
```

MySQL 用例要求目标库可写，会应用 V1–V18 迁移并写入、清理带唯一标记的日志行；Redis 用例使用 15 号键空间与唯一键名，并覆盖 RealtimeBus 的双实例 fanout。缺任一环境变量时对应用例 SKIP。

## 6. 最终回归结果（2026-10-24）

在 `feat/p5-residual-closure` 分支 `0e4f508` 上按顺序实跑：

```bash
cmake --build --preset debug
ctest --preset debug --output-on-failure
cd frontend
npm run test:unit
npm run build
npm run test:e2e
cd ..
python scripts/check-acceptance.py
python scripts/backup_restore_test.py
python scripts/run-external-tests.py --redis-image redis:7-alpine
python scripts/backup_restore_mysql_test.py
```

- 后端：`cmake --build --preset debug` 通过（Ninja 报告无待编译目标），`ctest` 注册 205 项，通过 202、失败 0、跳过 3（缺真实 MySQL/Redis 环境变量的 `ExternalStores.*` 与 `RealtimeBus.RedisFanoutReachesSecondInstance`），耗时 66.47 秒；`tests` 目录共 43 个测试源文件。
- 前端：`npm run test:unit` 13 个文件 30 项全部通过；`npm run build` 类型检查与构建通过；`npm run test:e2e` 9 项全部通过（本机 Edge）。
- 验收：`check-acceptance.py` 通过 86 项、失败 0、跳过 0，包含 h3、mTLS、OTLP mock、UDP 遥测、OIDC 与离线生命周期。
- 备份：`backup_restore_test.py` 运行 6 项，5 项通过，1 项 Windows 文件权限位用例按平台跳过；`backup_restore_mysql_test.py` 完成 MySQL 备份、归档校验与导入往返，目标库迁移版本为 18。
- 真机外部依赖：`run-external-tests.py --redis-image redis:7-alpine` 三项 3/3 通过、无跳过，耗时 10.06 秒（MySQL 7.61 秒、Redis 1.12 秒、双实例扇出 1.32 秒）。
- 迁移：V15–V18 存在，`TestMigrations` 期望 18 个版本并通过。
